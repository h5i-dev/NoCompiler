# 健全性の証明（自然言語）

## 結論と位置づけ

前提のもとで、検査を通った safe 関数は自分の署名の意味 ⟦σ⟧ を満たす。これを四つの定理に分けて示す。

| 定理 | 内容 |
| --- | --- |
| A 保存と前進 | 実行中のどの状態でも不変量が成り立ち、次の一歩がある |
| B 出口 | 戻りの命令に達したとき、署名の出口の条件が成り立つ |
| C 停止 | `partial` でない関数は、必ず戻るか exit する |
| D プログラム全体 | unsafe と外部の契約が成り立てば、すべての safe 関数が ⟦σ⟧ を満たす |

この証明の限界は次のとおりである。

- 自然言語の証明で、機械検査していない。誤りが残っている可能性がある。
- e5r 側の前提は、`Step.lean` と `Spec.lean` の定義を拾い読みして名前を対応させただけで、全文と突き合わせていない。
- 対象は設計タブの規則（フィールドの型を含む）で、算術は表に載せた命令だけを扱う。
- 前提 M2 は、e5r の現在の定義ではなく、11/23 に決めた変更後の権限の判定である。e5r 側の変更はまだ行っていない。最後の節で説明する。

証明を書く過程で、規則の誤りが四つ見つかった。フレームの能力を確かめる時点、`give` の範囲、貸す長さが負でないこと、能力の当て方が一対一であることで、どれも設計タブを直してある。以下は直した後の規則についての証明である。

## 前提

証明は次の前提に頼る。どれもこの証明の中では示さない。

### 機械

| 記号 | 前提 | e5r で対応すると見ているもの |
| --- | --- | --- |
| M1 | 命令はコード c から取り出して復号する。メモリへの書込みで命令は変わらない | `Step` が `c.instr s.pc` を使う |
| M2 | 幅 w のロードは、番地 a が w の倍数で、\[a, a+w) の全バイトが権限の読める領域のどれかに入っていれば進む。ストアは書ける領域について同じ | 変更後の `canRead`、`canWrite`。現在の定義は「領域の一つに収まる」で、これより厳しい。整列は `exec` の `aligned` |
| M3 | 一歩でメモリが変わるのは、権限の書ける領域の中だけ | `VerifiedImg.frame` |
| M4 | 権限 P′ が P 以下なら、P′ のもとでの一歩は P のもとでの一歩でもある。呼ばれた関数の実行は、呼んだ関数の実行の一部としてつなげられる | `Step.mono`、`VerifiedImg.call` |
| M5 | レジスタは 64 ビットの語で、`x0` は常に 0。各命令がレジスタに与える効果は RISC-V の仕様どおり | `exec` |
| M6 | 関数の入口では `ra` が 4 の倍数 | `Entry.retAligned` |
| M7 | 関数の権限は、署名の能力ごとの領域と、入口の `sp` の下 K バイトの領域からなる | `Spec.perm`、`stackRegion` |

### プロファイルの構造

R1–R6 の検査が保証すると見ているもの。

- **S1** ロード、ストア、`ecall` 以外の命令は必ず一歩進む。復号でき、飛び先は 4 の倍数で、関数の中か呼出し先の入口である。
- **S2** 関数の点には順序 τ があり（記録が与える。既定は番地の順）、関数内の制御の辺は、τ が増える前向きの辺か、注釈の付いたループ入口 h への戻りの辺 u → h（h は u を支配する）のどちらかである。各ループは τ の区間 [τ(h), τ(最後の戻りの辺の元)] をなし、ループは入れ子になっていて、本体へは入口からしか入れない。
  - *2026-11-23 P1 adopted (user)*: 以前は τ を番地の順に固定していた。clang のブロック配置では、帰約可能な制御フローでも番地の順ではループが区間にならないことが多い（musl の試行で 29 ファイル中 8）。帰約可能なグラフには、どの自然ループも連続する順序（たとえばループの本体を出る前に終える逆後順）が必ずあるので、その順序を記録に持たせ、番地の代わりに使う。以下の証明は「番地」を「τ」と読めばそのまま成り立つ。
- **S3** `sp` はプロローグで定数 F（16 の倍数）だけ下がり、エピローグで元に戻る。それ以外では変わらない。戻りと末尾呼出しは、`sp` が入口の値のときにだけ起きる。
- **S4** フレームの中で、スロットと「番地を取る範囲」は互いに重ならない。`sp` 相対のアクセスはスロットに対するものだけである。スロットは 8 バイトで、8 の倍数の位置にある。
- **S5** 呼出しグラフに循環がない。
- **S6** 記号の番地を表す変数の値は、リンク後の実際の番地に等しい。

### 環境、算術、契約

- **E1** システムコールの署名は、`Env.lean` の関係に対して正しい。
- **A1** 「Ψ ⊢ ψ」は「Ψ を満たすすべての整数の付値が ψ を満たす」という意味で、検査機がこれを認めたときは実際にそうである。
- **U1** unsafe と外部の関数は、それぞれの ⟦σ⟧ を満たす。トークンの不変条件は、そのトークンの足跡の中のメモリだけで決まる。
- **G1** `give` を受け取る側の権限についての仮の前提だった。権限の判定を全バイト単位に変えたので不要になり、廃止した。

## 定義

### D1 付値と型

付値 ι は添字変数に整数を割り当てる。添字式 e の値を ιe と書く。64 ビットの語 w の符号なしの値を ⌊w⌋ と書く（0 ≤ ⌊w⌋ < 2^64）。w が `int(e)` を満たすとは、⌊w⌋ ≡ ιe (mod 2^64) のことである。

### D2 能力の妥当性と足跡

- **バイト列の能力** `b ↦ bytes[n] m {k: int(e), …}` が状態 s で妥当とは、次が成り立つこと。範囲について 0 ≤ ιb、0 ≤ ιn、ιb + ιn ≤ 2^64。各フィールドについて 0 ≤ k、k + 8 ≤ ιn、8 ∣ ιb + k で、s のメモリの番地 ιb + k からの 8 バイトの語が `int(e)` を満たす。足跡は番地の集合 \[ιb, ιb + ιn)。（2026-11-24 追加、decisions.md I38、user の決定: `heap` の印が付いた能力では、さらに範囲が `Heap` トークンの生きている割当て単位の一つであること。単位の集まりはトークンの足跡だけで決まる。）
- **トークン** T は、足跡 fp(T)（論理上の値で、付値と一緒に選ぶ）と不変条件を持つ。妥当とは、s のメモリについて不変条件が成り立つこと。
- **条件付きの能力** `ψ ⇒ c` は、ι が ψ を満たすときは c と同じ。満たさないときは常に妥当で、足跡は空。

### D3 分離

能力の集まりが分離しているとは、`rw` の能力とトークンのどれについても、その足跡が、集まりの中のほかのすべての能力の足跡と交わらないこと。`ro` どうしは交わってよい。分離している集まりの一部を取り出しても、分離している。

### D4 一回の呼出し

関数 f の一回の呼出しを固定して、次の記号を使う。

| 記号 | 意味 |
| --- | --- |
| s0、ι0 | 入口の状態と、署名の `[…]` の変数への付値 |
| σ0 | 入口の `sp` の符号なしの値 |
| K、S0 | 署名の `stack` と、スタック領域 \[σ0 − K, σ0) |
| P0 | M7 の権限 |
| E | 入口の `rw` の能力とトークンの足跡の和 |
| Pool | `take` の能力の足跡と、借りたトークンの足跡の和。E は「借りた `rw` のバイト列の足跡」と Pool の和になる |

### D5 署名の意味 ⟦σ⟧

入口の条件:

- **P1** pc は f の入口で、`ra` は 4 の倍数。
- **P2** `in` のレジスタが型を満たす。
- **P3** ι0 が入口側の `where` を満たす。
- **P4** `borrow` と `take` の能力がすべて妥当。
- **P5** それらが分離している。どの足跡も S0 と交わらない。
- **P6** 16 ∣ σ0 かつ K ≤ σ0。

出口の条件（pc が s0 の `ra` の値になった状態について）:

- **Q1** `sp` と callee-saved のレジスタが s0 と同じ。
- **Q2** ι0 を `out` の新しい変数へ拡張した付値があって、`out` のレジスタが型を満たし、出口側の `where` が成り立つ。
- **Q3** `borrow` の能力は同じ範囲で妥当（フィールドは署名の出口側のもの）。返るトークンと `give` の能力は妥当。
- **Q4** 返る能力の全体（`borrow`、返るトークン、`give`）は分離している。返るトークンと `give` の足跡は Pool に含まれる。
- **Q5**（2026-11-24 追加、I38）入口で `Heap` の生きている単位で、Pool にも S0 にも掛からないものは、出口でも生きている単位である。呼出しの側では、手元に残した heap の能力は g の Pool（`take` に当てた能力と貸したトークンの足跡）と I5 で交わらず、S\_g とも交わらないので、g の Q5 で生きたまま残る。自分の Q5 は、実行に沿った帰納法で出る。そのために呼出しの検査は二つを足す。自分の `borrow` から来た能力を g の `take` に当てない。呼出しの時点で、`borrow` のそれぞれをその範囲全体のまま持っている。

**全の意味**: P1–P6 を満たすどの入口からも、権限 P0 のもとで実行は行き詰まらず、有限歩で、Q1–Q4 を満たす状態に達するか exit で終了する。

**部分の意味**: 実行は行き詰まらず、pc が s0 の `ra` の値になったときは Q1–Q4 が成り立つ。

「書ける範囲の外のメモリは変わらない」は定義に入れていない。M3 から出る。

### D6 不変量

f の中の各プログラム点 pc には、状態の型 (Δ; Ψ; Γ; Φ; C) とフレームの深さ d（S3 により 0 か F）が決まっている。A は、d = F のとき「番地を取る範囲」の和、d = 0 のとき空集合とする。状態 s と付値 ι（とトークンの足跡の選び方）について、Inv(pc, s, ι) とは次の全部が成り立つことである。

- **I1** ι は ι0 の拡張で、Ψ を満たす。
- **I2** 各レジスタの値が Γ の型を満たす。`sp` の値は σ0 − d。
- **I3** Φ の各スロット k について、番地 σ0 − d + k からの 8 バイトの語が Φ(k) を満たす。
- **I4** C の各能力が妥当。
- **I5** C が分離している。
- **I6** C の各能力の足跡 X について X ∩ S0 ⊆ A。
- **I7** C の各能力の足跡は、P0 の読める領域の和に含まれる。`rw` の能力とトークンの足跡は、書ける領域の和に含まれる。
- **I8** C の `rw` の能力とトークンの足跡は E ∪ A に含まれる。

I6 が言っているのは、能力がスタック領域にかかるのは「番地を取る範囲」の中だけ、ということである。スロットと、`sp` より下の領域は、どの能力にも入らない。

### D7 部分型

Σ ⊑ Σ′ とは、Σ′ がその点で新しく束縛する変数への添字式の割当て θ（ほかの変数は動かさない）があって、次が成り立つことである。

- Σ の Ψ から θΨ′ が出る。
- 各レジスタと、Σ′ の各スロットについて、二つの式が法 2^64 で一致することが Ψ から出る。
- Σ′ の各能力に、Σ の能力が一対一に対応する。範囲が等しいことが Ψ から出て、種類と印が同じで、Σ′ 側のフィールドは Σ 側の同じ位置にあって式が一致する。

Σ 側の余った能力、スロット、フィールド、事実は捨ててよい。

### D8 検査が通る

f が検査を通るとは、各プログラム点に状態の型が与えられていて（検査機が出力する記録）、次が成り立つことである。

- **T0** 入口の型は署名から決まる。Γ は `in` のとおりで、`ra`、`sp`、callee-saved はそれぞれ新しい変数 x による `int(x)`（`sp` は `int(σ0)`）。Ψ は入口側の `where`、能力から出る事実、0 ≤ σ0 < 2^64、16 ∣ σ0、K ≤ σ0。Φ は空。C は `borrow` と `take` の能力。
- **T1** 各命令と、そこから出る各辺 pc → pc′ について、規則の検査条件が Ψ から出て、規則が作る型 Σ\* が Σ\* ⊑ Σ(pc′) を満たす。記録が pc′ に型を与えないときは、Σ\* の事実から偽が出ること（その辺を通る実行はない）。
- **T2** `partial` でない関数では、各ループ入口 L に式 e があり、L への戻りの辺で、その辺の具体化 θ について 0 ≤ e かつ θe < e が Ψ から出る。

## 補題

以下、「規則」は設計タブの型付け規則を指す。

### 補題 1（代表元）

どの整数 v にも、v = x + 2^64·k、0 ≤ x < 2^64 となる整数 x、k がただ一組ある。語 w が ⌊w⌋ ≡ v (mod 2^64) を満たすなら x = ⌊w⌋ である。符号付きの範囲 −2^63 ≤ x < 2^63 についても同じことが言え、x は w の符号付きの値になる。

**証明** 整数の割り算の商と余りが一意であることから出る。∎

### 補題 2（算術）

Inv(pc, s, ι) が成り立ち、pc の命令が算術の表の命令で、s から s′ へ一歩進むとする。このとき ι を新しい変数へ拡張した ι′ があって、rd の新しい値は表の型を満たし、表の事実は ι′ で真で、規則が作る型について Inv が成り立つ。

**証明** 命令ごとに確かめる。

- `addi`、`add`、`sub`、`slli`、`shNadd`、定数との `mul`: 2^64 を法とすると、加算、減算、乗算は合同を保つ。元のレジスタの値が ιe と合同なので、結果は表の式の値と合同になる。新しい変数は要らない。
- `andi`（c ≥ 0）: 結果 x は ⌊w⌋ と c のビットごとの積で、0 ≤ x ≤ c。c = 2^k − 1 のとき x = ⌊w⌋ mod 2^k。⌊w⌋ ≡ ιe (mod 2^64) で、2^k は 2^64 を割るから、ιe ≡ x (mod 2^k)。つまり ιe = x + 2^k·j となる整数 j がある。チェッカーはこの j も新しい変数として型に書く（ι′ は j に (ιe − x)/2^k を割り当てる）。こうすると、商に名前を付けた型（ループの頭の型など）と式が一致し、具体化が j を見つけられる。
- `srli`: 結果 x は ⌊w⌋ を 2^c で割った商。補題 1 より ⌊w⌋ = u(ιe) なので、u = 2^c·x + r、0 ≤ r < 2^c。
- `minu`: x は ⌊w1⌋ と ⌊w2⌋ の小さいほう。
- `remu`: 除数が 0 でなければ x は剰余で 0 ≤ x < ⌊w2⌋。規則は Ψ から u(e2) > 0 が出るときにだけこの事実を足す。
- 32 ビット演算: 結果は下位 32 ビットの和を符号拡張した語で、その符号付きの値 x は −2^31 ≤ x < 2^31 かつ x ≡ ιe1 + ιe2 (mod 2^32)。
- 表にない命令: x を結果の符号なしの値にする。

既存の変数の値は変えないので Ψ は真のまま（I1）。メモリと能力は変わらないので I3–I8 はそのまま。∎

### 補題 3（分岐）

分岐の規則が各辺に足す事実は、その辺を通った状態で真である。

**証明** `bltu` は ⌊w1⌋ < ⌊w2⌋ のときに成立する。補題 1 より ⌊wi⌋ = u(ιei)。`blt` は符号付きの値で同じ。`beq` は w1 = w2 のときに成立し、これは ιe1 ≡ ιe2 (mod 2^64)、すなわち 2^64 が ιe1 − ιe2 を割ることと同じである。∎

### 補題 4（弱化）

型 Σ について Inv が付値 ι で成り立ち、Σ ⊑ Σ′ が θ で成り立つなら、Σ′ について Inv が成り立つ。付値は、Σ′ の新しい変数 y に ι(θy) を割り当て、ほかは ι のままにしたもの。

**証明** I1 は「Ψ から θΨ′ が出る」ことと A1 から。I2、I3 は式が法 2^64 で一致することから。I4–I8 はどれも「C の各能力について」「C が分離している」という形なので、能力やフィールドを捨てても成り立つ。範囲が等しいことが Ψ から出るので、足跡は変わらない。∎

### 補題 5（ロード）

Inv(pc, s, ι) が成り立ち、命令が幅 w のロードで、a = e\_rs + c と能力 κ = `b ↦ bytes[n] …` について検査条件 b ≤ a、a + w ≤ b + n、w ∣ a が Ψ から出るとする。このとき一歩進み、進んだ後の状態で規則の型について Inv が成り立つ。

**証明** 実際の番地の語は ιa と合同である。I4 より 0 ≤ ιb かつ ιb + ιn ≤ 2^64 なので、0 ≤ ιa かつ ιa + w ≤ 2^64。よって実際の番地の符号なしの値は ιa そのもので、折返しは起きない。\[ιa, ιa + w) は κ の足跡に含まれ、I7 より全バイトが読める領域に入る。w は ιa を割る。M2 より一歩進む。

結果の型について。規則がフィールド `k: int(e)` を使うのは、8 バイトのロードで a = b + k が Ψ から出るときである。このとき読んだ語は番地 ιb + k の語で、I4 より `int(e)` を満たす。それ以外では、読んだ値を新しい変数の値にする。幅と符号拡張から範囲の事実が出る。メモリは変わらない。∎

### 補題 6（ストア）

補題 5 と同じ仮定で、命令が幅 w のストア、κ が `rw` とする。このとき一歩進み、進んだ後の状態で規則の型について Inv が成り立つ。

**証明** 進むことは補題 5 と同じ議論で、I7 の書ける領域についての主張を使う。変わるメモリは W = \[ιa, ιa + w) だけで、W は κ の足跡に含まれる。

- **I3** スロットは S0 の中にあり、S4 より A の外にある。I6 より κ の足跡は S0 の中では A にしかかからない。よって W はスロットと交わらず、スロットの中身は変わらない。
- **I4、κ 以外の能力** κ は `rw` なので、I5 よりほかのどの能力の足跡とも交わらない。ほかの能力のフィールドの中身は変わらない。トークンの不変条件は足跡の中のメモリだけで決まるので（U1）、保たれる。
- **I4、κ 自身** 規則が残すフィールドは、W と重ならないことが Ψ から出たものだけなので、中身は変わらない。規則が置き換えるフィールド k は、8 バイトのストアで a = b + k のときで、書いた語は rs2 の値だから Γ(rs2) を満たす。位置の条件 8 ∣ ιb + k と k + 8 ≤ ιn は、整列と範囲の検査条件そのものである。8 の倍数の番地にある二つの 8 バイトのフィールドは、一致するか交わらないかのどちらかなので、置き換えがほかのフィールドを部分的に壊すことはない。
- **そのほか** 付値、レジスタ、足跡は変わらないので I1、I2、I5–I8 はそのまま。∎

### 補題 7（フレーム）

(a) `sp` を F だけ下げる命令の後、「番地を取る範囲」R\_i ごとに `rw` の能力を足した型について Inv が成り立つ。検査条件は F ≤ K。

**証明** R\_i は \[σ0 − F, σ0) に含まれ、F ≤ K より S0 に含まれる。妥当性: K ≤ σ0 と σ0 < 2^64（T0、P6）から、R\_i の下端は 0 以上、上端は 2^64 以下。I5: R\_i どうしは S4 で交わらない。以前からの能力の足跡 X は、d = 0 の I6 より X ∩ S0 = ∅ なので R\_i と交わらない。I6: 新しい A は R\_i の和で、R\_i ⊆ A。以前からの能力は X ∩ S0 = ∅。I7: S0 は書ける領域の一つ（M7）。I8: R\_i ⊆ A。∎

(b) `sp` を戻す命令で、各 R\_i について「範囲がちょうど R\_i の `rw` の能力」が一対一にあることが Ψ から出るとする。それらとスロットを捨てた型について、d = 0 の Inv が成り立つ。

**証明** 残る能力の足跡 X を取る。捨てた能力は `rw` なので、I5 より X はどの R\_i とも交わらない。つまり X ∩ A = ∅。これと I6（X ∩ S0 ⊆ A）から X ∩ S0 = ∅ が出て、これが d = 0 の I6 である。I8 は X ⊆ E ∪ A と X ∩ A = ∅ から X ⊆ E。ほかの条件は、能力を捨てても成り立つ。∎

### 補題 8（呼出し）

Inv(pc, s, ι) が成り立ち、命令が g の呼出しで、呼出しの検査が具体化 θ で成り立ち、g が ⟦σ\_g⟧ を全の意味で満たすとする。g のスタック領域を S\_g = \[σ0 − d − K\_g, σ0 − d) と書く。このとき次が成り立つ。

1. 呼出し直後の状態は、g の入口の条件 P1–P6 を満たす。
2. g の権限は P0 以下である。
3. g が戻った状態で、規則が作る型について Inv が成り立つ。

**1 の証明**

- **P1** `jal` は `ra` に pc + 4 を入れる。4 の倍数である。
- **P2、P3** 引数と制約の検査そのもの。付値は、g の変数 y に ι(θy) を割り当てたもの。
- **P4** `borrow` に当てた能力を `b0 ↦ bytes[n0]` とする。検査 b0 ≤ θb、θb + θn ≤ b0 + n0、0 ≤ θn と I4 から、貸す範囲は 0 以上 2^64 以下に収まり、長さは負でない。フィールドは、検査が求める一致と I4 から。`take` とトークンは I4 そのまま。（2026-11-23 訂正: I4 が覆うのは持っている能力のオフセットだけで、貸す長さの中にあることは言わない。検査はさらに各フィールド k について Ψ ⊢ k + 8 ≤ θn を求め（decisions.md I33.1、Lean では `Fn.fieldsLent`）、フィールドの成立はこの検査と、同じ番地にある持っている能力のフィールドの成立から出る。）
- **P5、能力どうし** g の `rw` の句 β と、ほかの句 β′ を比べる。当てた能力が違うとき: β に当てた能力は `rw` なので、I5 よりほかの能力と交わらず、貸す範囲はそれぞれ当てた能力の中にあるから交わらない。当てた能力が同じとき: 検査が、二つの範囲が交わらないことを直接求めている。`take` に当てた能力はほかの句に当てられないので、同じ議論が使える。トークンは I5。
- **P5、スタック** スタックの検査 d + K\_g ≤ K より S\_g ⊆ S0。貸す範囲 X は I6 より X ∩ S0 ⊆ A。A は \[σ0 − d, σ0) に含まれ、S\_g はその下にある。よって X ∩ S\_g = ∅。
- **P6** g の入口の `sp` は σ0 − d。16 ∣ σ0（T0）と 16 ∣ d（S3）から 16 で割れる。K\_g ≤ σ0 − d は K ≤ σ0 とスタックの検査から。

**2 の証明** g の権限の領域は、貸した範囲、`take` の能力、トークンの足跡を表す領域、S\_g である。貸した範囲と `take` の能力は、当てた能力の足跡の中にあり、I7 より P0 の領域の和に含まれる。S\_g は S0 に収まる。トークンの足跡も I7 より書ける領域の和に含まれる。全バイト単位の判定では、これだけで g の権限が P0 以下であることが出る。`rw` で貸すときは当てた能力が `rw` なので、書ける領域についても同じ。∎

**3 の証明** 1、2 と ⟦σ\_g⟧、M4 より、実行は P0 のもとで g の出口の状態に達するか、exit で終了する。達したとする。M3 より、その間に変わったメモリは W\_g の中だけである。W\_g は、`rw` で貸した範囲、`take` の足跡、貸したトークンの足跡、S\_g の和。

- **pc** g は `ra` の値、つまり呼出しの次の命令へ戻る。
- **I1、I2** Q1 より `sp` と callee-saved は同じ値。`out` のレジスタと出口側の `where` は Q2。ほかのレジスタは、その値を新しい変数に割り当てる。
- **I3** スロットは \[σ0 − d, σ0) の中で A の外にある。S\_g はその下にある。W\_g の残りは能力の足跡の中で、I6 より S0 の中では A にしかかからない。よってスロットは変わらない。
- **I4、手元に残した能力 κ** κ のフィールドが W\_g と交わらないことを見る。S\_g とは I6 で交わらない。`take` の足跡とトークンの足跡とは I5 で交わらない。`rw` で貸した範囲は、別の能力から貸したものなら I5 で交わらず、κ 自身から貸したものなら、規則がその範囲と重なり得るフィールドを捨てている。手元に残したトークンの不変条件も同じ理由で保たれる。
- **I4、返ってきた能力** Q3。
- **I5** 新しい能力（`give` と返るトークン）の足跡は、Q4 より g の Pool、つまり `take` に当てた能力と貸したトークンの、呼出し前の足跡の和に含まれる。手元に残した能力は、呼出し前の I5 よりこれらと交わらない。新しい能力どうしは Q4 で分離している。（2026-11-23 補足、Lean の証明から: トークンの足跡は名前ごとの値なので、貸したトークンの名前を持つ能力が C に二つあると、呼出しの後は両方が g の足跡になり交わる。検査は、貸すトークンの名前を持つ能力が C にちょうど一つであることを求める（Lean では `callAt` の条件）。また、呼出しの後の型では、callee-saved でも `out` でもないレジスタにそれぞれ新しい変数を与える。）
- **I6、I8** 新しい足跡は、呼出し前に C にあった `rw` の能力とトークンの足跡の和に含まれる。それらは I6、I8 を満たしていた。二つの条件は和と部分集合を取っても成り立つ形をしている。
- **I7** `give` の能力と返るトークンの足跡は、呼出し前に書ける領域の和に含まれていた足跡の和に含まれる。∎

### 補題 9（システムコール）

E1 のもとで、`ecall` について補題 8 と同じ結論が成り立つ。

**証明** `write` と `read` が進む条件は、バッファの全バイトが読める、または書ける領域に入ることである。これは `borrow` の照合と I7 から出る。`read` が書くのは貸した範囲の中だけなので、補題 8 の 3 の議論が S\_g を空としてそのまま使える。`a0` 以外のレジスタは変わらない。結果の範囲は E1。`exit` は実行を終了させる。∎

### 補題 10（戻り）

Inv(pc, s, ι) が成り立ち、命令が `jalr zero, 0(ra)` で、戻りの検査が成り立つとする。このとき一歩進んで pc は s0 の `ra` の値になり、Q1–Q4 が成り立つ。

**証明** 検査より `ra` の値は入口と同じで、P1 より 4 の倍数だから、S1 より進む。Q1、Q2 は検査そのもの。Q3 は I4 と、`borrow` に当てた能力の範囲が入口と等しいことから。Q4 の分離は、返す能力が C の一部であることと I5 から。

Q4 の Pool について。S3 より d = 0 で A は空だから、I8 より `rw` の能力とトークンの足跡は E に含まれる。E は「借りた `rw` のバイト列の足跡」と Pool の和である。借りた `rw` のバイト列を返す義務には、範囲が入口と等しい `rw` の能力を当てている。`give` と返るトークンに当てた能力は、当て方が一対一なのでそれらとは別の能力で、I5 よりそれらの足跡と交わらない。よって Pool に含まれる。`give` できるのが `rw` の能力とトークンだけ、という制限をここで使っている。∎

## 定理

### 定理 A（保存と前進）

f が検査を通り（D8）、f が呼ぶすべての関数が ⟦σ⟧ を全の意味で満たすとする。P1–P6 を満たす入口から始まる実行で、f の命令に達するたびに、ある付値 ι について Inv(pc, s, ι) が成り立ち、次の一歩がある。呼んだ関数の中の実行は、まとめて一歩と数える。

**証明** f の命令に達した回数についての帰納法。

入口。T0 の型について Inv を確かめる。付値は、ι0 に `ra`、`sp`、callee-saved などの入口の値を足したもの。I1: 入口側の `where` は P3、能力から出る事実は P4、`sp` の事実は P6。I2: 付値の取り方と P2。I3: Φ は空。I4: P4。I5: P5。I6: d = 0 で、P5 よりどの足跡も S0 と交わらない。I7: M7 より、入口の能力はそれぞれ権限の領域の一つ。I8: E の定義そのもの。

一歩。Inv(pc, s, ι) が成り立つとする。T1 より規則の検査条件が Ψ から出て、I1 と A1 より ι のもとで実際に成り立つ。命令の種類ごとに、進むことと、進んだ後に規則の型 Σ\* で Inv が成り立つことが出る。

| 命令 | 進むこと | 進んだ後の Inv |
| --- | --- | --- |
| 算術 | S1 | 補題 2 |
| 分岐、関数内のジャンプ | S1 | 補題 3 |
| ロード、ストア | 補題 5、6 | 補題 5、6 |
| `sp` の上げ下げ | S1 | 補題 7 |
| 呼出し | S1 と補題 8 | 補題 8 |
| `ecall` | 補題 9 | 補題 9 |

スロットへの `sd` と `ld` は、番地が S0 の中にあるので M7 と M2 で進み、書く場所はどの能力の足跡にも入らない（I6 と S4）ので、Φ のそのスロットだけが変わる。

最後に、T1 の Σ\* ⊑ Σ(pc′) と補題 4 より、次の点の型について Inv が成り立つ。∎

### 定理 B（出口）

定理 A と同じ仮定で、実行が戻りの命令に達したら、次の状態で Q1–Q4 が成り立つ。

**証明** 定理 A より戻りの命令で Inv が成り立つ。補題 10 を当てる。∎

### 定理 C（停止）

f が `partial` でなく、T2 を満たし、呼ぶ関数がすべて ⟦σ⟧ を全の意味で満たすなら、実行は有限歩で戻るか exit する。

**証明** 背理法。戻りも exit もせずに無限に続くとする。呼んだ関数は必ず戻るので、f の命令が無限回実行される。前向きの辺は τ を増やすから、戻りの辺が無限回通られる（S2）。

戻りの辺が無限回通られるループのうち、いちばん外側のものの入口を L とする。L を囲むループの戻りの辺は、有限回しか通られない。L の本体から外へ出た後で再び L に来るには、τ を戻る必要があり、それは L を囲むループの戻りの辺でしか起きない（S2）。したがって、ある時点から先、実行は L の本体の中にとどまり、L には戻りの辺からだけ着く。

その時点から先、L に着くたびの付値を ι\_1、ι\_2、… とする。添字変数の値は変わらない。内側のループの入口で型を取り直すときも、D7 の θ はその点で新しく束縛する変数しか動かさない。だから L に着いてから次の戻りの辺まで、L の注釈の変数の値は ι\_j のままである。T2 より、戻りの辺で 0 ≤ ι\_j(e) かつ ι\_{j+1}(e) < ι\_j(e)。負でない整数が無限に減り続けることになり、矛盾する。∎

*2026-11-23 P1 adopted (user)*: 番地を τ に置き換えた（S2 の注を参照）。Lean の証明（`lean/NoCompiler/Typed/Sound/Rank.lean`）は、この背理法の代わりに、ループごとの成分（入口より前 / 本体の中で測度 / 後）を τ の小さい入口から並べた辞書式の順位が、受理されたどの辺でも真に減ることを示している。

### 定理 D（プログラム全体）

前提のもとで、検査を通ったすべての safe 関数は ⟦σ⟧ を満たす。`partial` でない関数は全の意味で、`partial` な関数は部分の意味で満たす。

**証明** S5 より呼出しグラフに循環がないので、呼ばれる側から順に並べて帰納法を使う。関数 f が呼ぶ関数は、unsafe か外部なら U1、safe なら帰納法の仮定により ⟦σ⟧ を満たす。`partial` でない f は `partial` な関数を呼ばない（呼出しの検査）ので、呼ぶ関数はすべて全の意味で満たす。行き詰まらないことは定理 A、出口の条件は定理 B、停止は定理 C から出る。∎

### `partial` な関数

f が `partial` で、呼ぶ関数 g が部分の意味でしか ⟦σ⟧ を満たさない場合、補題 8 の 3 は「g が戻れば」という条件付きになる。g が戻らないとき、g の実行は g の権限のもとで行き詰まらずに続き、補題 8 の 2 と M4 より、それは P0 のもとでも行き詰まらない実行である。よって定理 A と定理 B はそのまま成り立つ。定理 C は主張しない。

### 末尾呼出し

末尾呼出しの検査は、「呼出しの検査」に加えて「g の出口の型から作った状態が f の戻りの検査を満たす」ことである。S3 より末尾呼出しの時点で `sp` は入口の値で、検査より `ra` と callee-saved も入口の値である。g はその `ra` へ戻り、g の Q1 はそれらを保つ。残りは補題 8 と補題 10 の議論を続けて当てればよい。

## この証明が頼っているものと、弱い箇所

いちばん大きな依存は、e5r の権限の判定を変えるという 11/23 の決定である。e5r 側の変更はまだ行っていない。

### 権限の判定を変えたこと

e5r の現在の定義は「アクセスが領域の一つに収まる」ことを求める（`Region.covers`）。この証明の M2 は「アクセスする全バイトが、読める（書ける）領域のどれかに入っている」という変更後の判定である。

変更前の判定のままだと、型の検査を通るアクセスが行き詰まる場合がある。`give` で返ってくる能力が、受け取る関数の権限の二つの領域にまたがるときである。たとえば関数が呼出し元から受け取ったブロックを `free` し、続けて `malloc` したとき、アロケータが隣の空き領域とつなげて返すと起きる。変更後の判定ではこの食い違いがない。

残っている作業は三つある。

1. `Step.lean` の `canRead` と `canWrite` の定義を変える。
2. 「古い判定で成り立つ結果は、新しい判定でも成り立つ」ことを補題として示し、既存の証明を移す。新しい判定は古い判定より緩いだけなので成り立つ見込みだが、証明していない。
3. `trust.md` を更新する。

「領域の一つに収まれば十分」という補題を残せば、普段の証明の書き方は変わらない。

### そのほかの弱い箇所

- **機械検査していない。** 特に補題 8 は場合分けが多く、見落としがあり得る。設計の誤りが四つ見つかったのもこの補題と補題 7、10 を書いているときで、まだ残っていると考えるほうが自然である。
- **前提 M と S を e5r の定義と突き合わせていない。** S2（制御の形）と S4（スロットと番地を取る範囲）は、プロファイルの検査がこの形で保証しているかを確かめる必要がある。S4 のうち「番地を取る範囲」は、以前の仕様案で足した R6 に頼っている。

- **再帰を扱っていない。** S5 を外すと、定理 D の帰納法が使えない。
- **算術の表にない命令の精度。** 健全性には響かないが、表を広げるたびに補題 2 に場合を足す必要がある。
