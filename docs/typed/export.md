# Export from the Rust checker to the Lean checker

U proposes the format here; T agrees or amends. This section is T's list of what the
Lean checker needs, written before the format exists (2026-11-23).

## What the Lean checker reads

The Lean checker (`lean/NoCompiler/Typed/Check.lean`, in progress) checks a function
**against the decoded code image** (`Code`, the `.text` words of the linked ELF), never
against assembly text. Everything else is a hint it re-checks:

1. **Per function**: entry address, size in bytes, its signature (`Typed.Sig`), and the
   `partial` flag.
2. **Variable numbering**: index variables are numbers (I11). Per function: the numbers of
   the signature's parameters and `out` variables, one variable per entry register for
   `ra`, `sp`, `gp`, `tp`, `s0`–`s11` (`regVar`), the loop-head variables, and a base above
   which the checker may allocate fresh variables. Display names are optional.
3. **The record (note, "今から守っておくこと" 3)**: for every instruction address of the
   function, the state type before it: registers → index expressions (a register not listed
   is `int`), facts, slots, capabilities (with the borrow clause each came from), frame
   depth. This is the Rust checker's per-point state after joins and loop heads.
4. **Loops**: for each head, its bound variables and `decreases` expression.
5. **Callees**: for each call target address, the callee's signature and `partial` flag.
6. Optional: per edge, the instantiation θ of the target's new variables; per query, a
   cutting-plane certificate (`Typed.Cert`). Without them the Lean side computes its own.

A `.lean` file with these as definitions is simplest for T (one per program); JSON with a
small Lean reader is also fine.

## The format (U's proposal, 2026-11-23; T: amend here)

`nocompiler-typed check FILE.s --export-lean OUT.lean` writes a Lean module
`NoCompiler.Typed.Export.<file stem>` (`import NoCompiler.Typed.Check`) with:

- `sig_<name> : Sig` for every signature in the file (safe, unsafe, extern; callees too).
  `pre`/`post` are the conjunction of the clauses. `borrow[i].outFields` are the exit fields
  (the entry fields when the source has no `->`, I6). `u64(e)`/`i64(e)` became range facts.
- `fn_<name> : Fn` for every safe function **the Rust checker accepted** (none for rejected
  ones), following item 1–5 above:
  - `entry`: the function's byte offset in its section (`.text` or `.text.<name>`), not an
    image address; the Lean side takes the symbol's address from the image and uses this
    only to cross-check. `size`: words (a `call`/`tail` pair counts two, I21).
  - `regVar`: `(reg, var)` for `ra`, `sp`, then `gp`, `tp`, `s0`–`s11`.
  - `loops`: `head`, `last` as word indices, the `inv [...]` variables, `meas` (`⟨0, []⟩` in a
    `partial` function without a measure).
  - `types`: `(word index, STy)` for every reached instruction: all registers 1–31 with their
    expressions (a fresh variable = `int`), the facts Ψ (capability facts are not listed:
    they follow from `caps`, as in the Rust checker), capabilities with their identity and
    `origin` (= the `borrow` clause index for entry borrows). No entry for the second word
    of a `call`/`tail` pair, nor for unreached instructions.
  - `fresh`: every variable used is below it.
- Variables are numbers (`Var := Nat`): one numbering per file, shared by all signatures and
  functions in it. Display names: the JSON's `names[i]`.

Not in the Lean `STy` yet, so only in the JSON: slots Φ, frame depth, frames, `partial`,
instantiations θ, queries. `--export-json OUT.json` writes the same content plus those
(`format: "nocompiler-typed export v0"`; integers that can exceed 2^53 are strings;
`IExpr` is `{"const", "terms": [[coef, var]]}`; `Constr` is `"tt" | "ff" | {"le": [a, b]} |
{"eq": [a, b]} | {"dvd": [c, e]} | {"and": [...]} | {"or": [...]} | {"not": f}`).

Not done: θ per edge and solver certificates (item 6). The Lean file is generated by
string printing and has not been compiled by U (U runs no Lean); T, please report the first
error you hit and I will fix the printer.

### Static data in the export (2026-11-23, T's request)

Every exported signature carries the program's data symbols: each symbol's address variable
ℓ_sym is appended to `params`, `pre` gains `0 ≤ ℓ_sym`, `ℓ_sym + size ≤ 2^64` and
`align ∣ ℓ_sym`, and each **read-only** symbol becomes a `borrow ℓ_sym ↦ bytes[size] ro {fields}`
clause after the signature's own (exit fields = entry fields). In the record, the implicit
capabilities' `origin` is that clause's index. Writable symbols get no clause; a signature
lends them explicitly (`@sym`, I32).

### τ (2026-11-23, P1 adopted as the default, I36)

`Fn` gains `tau : List Nat`: the word indices of the reached points in the checker's order
τ. Every edge other than a back edge goes from an earlier to a later point of `tau`; each loop
is the τ-interval from `Loop.head` to `Loop.last`, where `last` is now the word index of the
loop's last point **in τ** (not the largest address); no edge enters an interval except at its
head. The JSON has the same list as `"tau"`. Under `--loops interval`, `tau` is the address
order. T: please add the field to `Fn` (the generated `.lean` already writes `tau := [...]`).

### Callees (2026-11-23, T's ask 6)

`fn_<name>` gains `callees := [(addr, sig_<g>), …]`: for every function `g` it calls (`jal`,
`call`/`tail` pairs) that has a signature and lies in the same file and section, `g`'s entry
address in the image (its section offset, as `entry`) with `sig_<g>`, the signature it is called
at. Callees in other files or sections have no address before linking and are left out; the
Lean checker then rejects the call (no matching `callees` entry), which is the safe direction.
With `--image` (below) every callee with a signature gets its linked address, in any file.

### Canonical numbering (2026-11-24, decisions.md P7 step 1)

Every exported signature numbers its variables canonically: its parameters 0.. in order, then
its `out` variables. Each function's record uses the same numbering for those, then its other
variables in increasing order (a bijection of `[0, fresh)`; `fresh` is printed as at least the
bijection's size). The same signature text therefore gives the same `Sig` in every file, which
the ledger across files needs. Step 2: a signature lists only the data symbols its function
uses (its own `auipc %pcrel_hi` symbols, those its clauses mention, and its callees', by a
fixpoint), and the record drops the other symbols' capabilities and facts. Step 3 (`link
--prove`) is not done.

### Linked image (2026-11-23, static data in Lean)

`nocompiler-typed check FILE.s --export-lean X.lean --image a.out` reads the symbol table of the
linked ELF (ET_EXEC/ET_DYN) and then:
* `entry` of each `fn_*` is the function's linked address, and `callees` lists every called
  function with a signature at its linked address;
* for each data symbol with an address, `ℓ_sym = address` is added to every signature's `pre`
  and to the facts of every exported point. The Lean checker types `auipc` with the literal
  `pc + (imm<<12)` (T, I21), so the literal and the data capability `ℓ_sym ↦ bytes[size]` meet
  in the solver. ⟦σ⟧ is unchanged: the equation is an ordinary entry constraint, which the
  caller (or the loader, for `_start`) establishes.
* in the exported point types (not the signatures) each ℓ_sym is replaced by its address, so
  an access at `auipc`'s literal address has a constant offset into the data capability and
  reads its fields (`capSub` compares bases by entailment; the equation makes them equal);
* each `auipc rd, %pcrel_hi(sym)`'s variable L (the paired `%pcrel_lo` immediate, I30) is the
  linker's value: with P the auipc's address and S the symbol's, hi = (S − P + 0x800) >> 12 and
  L = S − P − hi·2^12, so `rd` is the literal P + hi·2^12 the Lean checker computes;
* a `call`/`tail` pair (two words, I21) gets a type at its second word too: the type before the
  pair with the temporary (`ra`, `t1`) holding the auipc's literal for the callee's address;
* `def prog : List Fn` lists the exported functions callee-first (S5), for `Prog.check`.
Without `--image` the export is as before (section offsets, same-section callees, ℓ_sym free).

### The ledger's `proved` (2026-11-23)

`check FILE.s --image a.out --export-lean X.lean --prove [--lean-dir DIR] --ledger L.json`: for a
closed program (every callee of every exported function is exported), the module also gets the
linked `.text` (`def code`), `chk_<f> : fn_<f>.check code = true` per function and
`prog_checked : Prog.check code [] prog = true` (all by `decide +kernel`: the kernel's check,
no extra axiom), and `prog_meets` (theorem D, `Prog.check_sound_closed`). `--prove` compiles it
with the repository's Lean checker (`lake env lean`, in `--lean-dir`, `$NOCOMPILER_LEAN_DIR` or
the repository's `lean/`) and reads `#print axioms prog_meets`. Only if that succeeds with the
standard axioms (propext, Classical.choice, Quot.sound) does the ledger say `proved` for those
functions, with the module, the theorem, its axioms and each function's callees as evidence;
otherwise they stay `checked` and the reason is printed. `xorBits := [k, …]` in `fn_*` lists the
bit counts of the masks the xor-then-mask rule used (a hint for the Lean xor rule). A partial
signature is exported with `isPartial := true` (I19); theorem D covers total programs only, so
`--prove` is not attempted when an exported function is partial.

### θ per edge (2026-11-23, T's ask 4)

For each exported function, `theta_<name> : List (Option Nat × Nat × List (Var × IExpr))`
lists, for every edge into an `inv`/`join` point, the source word (`none`: the function's
entry), the target word, and the instantiation θ of the target's bound variables (the
`inv [...]` variables and the fresh variables of registers the annotation leaves as `int`).
It is a separate definition so `Fn` needs no new field; the JSON has the same as `"thetas"`
(`{"from", "to", "theta": [[var, IExpr]]}`). A hint: the Lean checker re-checks D7 with it.

### Frames (2026-11-23, T's fields)

`fn_<name>` has `frame := some { size, slots, addr }` when the signature has a `frame` clause
(offsets from the lowered `sp`, I8), and each `STy` has `slots := [(offset, IExpr)]` (Φ) and
`depth := 0 | size`. Frame capabilities have origin `none`.
