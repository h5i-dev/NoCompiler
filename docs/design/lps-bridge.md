# The Lean port of LPS and the bridge to NoCompiler

`lean/LPS` is a Lean port of LPS (theorem-labs/rocq-linux-process-semantics at f1006fe8, MIT License,
Copyright (c) 2026 Theorem Labs, PBC), the Linux process semantics oss-verify's theorems are stated in.
`lean/LPS/Bridge` relates NoCompiler's machine (`lean/NoCompiler`) to it, so that a theorem proved with
NoCompiler can be carried to a statement in LPS's terms. This page says what is proved, what is only
checked by running, and how to reproduce each check. Background and the comparison with oss-verify's
proofs: docs/design/prior-art-lps.md.

## What the bridge proves

All theorems below, and every theorem under `lean/LPS`, depend only on `propext`, `Classical.choice`, `Quot.sound`: `lean/LPS` is a default build target and among the axiom audit's roots (`lake exe nocompiler-audit`).

| Theorem | File | Statement |
|---|---|---|
| `toLPS` | `Bridge/Decode.lean` | NoCompiler's instructions as LPS's (`none` for Zba/Zbb, which LPS does not model) |
| `sim_step_reg`, `sim_step_load`, `sim_step_store` | `Bridge/Step.lean`, `Bridge/StepStore.lean` | from related states (`Rel`: registers, pc, memory under the permission, no pending syscall), one NoCompiler step of any non-`ecall` instruction is one `RiscvSemantics.step`, ending related, given the per-image facts at the pc |
| `codeAgree`, `codeAgree_sound` | `Bridge/Image.lean` | the per-image facts as one Boolean check over a code image: LPS fetches the same word, and the two decoders agree on it |
| `sim_sstep` | `Bridge/Proc.lean` | a bridged machine step is an LPS process step (`sstep_cfg_instr`) with the model unchanged, given no lazily backed pages (those come only from `MAP_NORESERVE`) |
| `sim_ecall`, `syscall_args_rel` | `Bridge/Ecall.lean` | at an `ecall`, LPS's step marks the syscall pending with NoCompiler's a7; LPS's six syscall arguments are NoCompiler's a0..a5 |
| `*_admits` | `Bridge/Syscalls.lean` | for each syscall fuzz_qdisc makes, an outcome LPS's `syscall_spec` admits, under stated conditions: `set_tid_address`, `openat` (read-only, existing file), `brk`, `mmap` (anonymous; `MAP_FIXED PROT_NONE` on a free range and inside a mapping), `read` (file), `close`, `ioctl` (ENOTTY), `writev` (to an output channel, the full write), `munmap`, `exit_group` |
| `codeAgree_hex`, `codeAgreeH_of_ranges`, `codeFacts_ofChunks` | `Bridge/HexStr.lean`, `Bridge/HexImage.lean`, `Bridge/Chunks.lean` | on an image whose segments are numbers (`SegH`), `codeAgree` equals a check the kernel evaluates on numbers, splittable into ranges; one check per chunk of a `nocompiler export` gives the per-image facts for the whole code |
| `*_covers`, `*_refines` | `Bridge/Refine*.lean` | NoCompiler's kernel model against LPS's syscall specs, syscall by syscall (next section) |

The `*_admits` lemmas are about LPS's specs alone; `Refine*` relates them to NoCompiler's kernel model.

## What is checked by running (differential tests)

On fuzz_qdisc plain (examples/qdisc, rv64imfd build, ELF sha256 a7ed3fa9…) with examples/qdisc's `in.ok`,
against `qemu-riscv64 -strace`:

1. `Examples/LPS/Test/DiffQemuRun.lean` + `examples/qdisc/diff_qemu.py`: the pc trace of the ported machine step to
   the first syscall, with resynchronisation.
2. `Examples/LPS/Test/DiffRunQdisc.lean` + `examples/qdisc/diff_syscalls.py`: the machine step through all 16 syscalls
   with a hand-written resolver (kernel choices replayed from qemu): 16 of 16 equal (numbers, arguments,
   returns), stdout and exit status equal, no resynchronisation.
3. `Examples/LPS/Test/DiffRunQdiscModel.lean` + `examples/qdisc/diff_syscalls_model.py`: LPS's own configuration
   from `init_config` with a valid LPS entry (sp `0x7ffffff00e70`, brk `0x4e000`, mmap addresses below
   `alloc_top`); at each syscall the conditions of its `*_admits` lemma are evaluated on LPS's input and
   model, and the next state is the one the lemma states. Result: 16 of 16 conditions hold, no lazy pages,
   0 mismatches with qemu after translating stack and mmap addresses, stdout and exit status equal.

Reproduce (after `examples/qdisc/gen_qdisc_images.sh` and a build of `LPS`):

```
cd lean
lake build Examples.LPS.Images.QdiscPlainE5r LPS.OSSVerify.Core.Shapes LPS.Bridge.Syscalls
lake env lean --run Examples/LPS/Test/DiffRunQdiscModel.lean IN.ok > lean.out
qemu-riscv64 -strace fuzz_qdisc.plain.elf IN.ok > out.txt 2> strace.txt
python3 ../examples/qdisc/diff_syscalls_model.py lean.out strace.txt out.txt 0x7ffffff00e70 SP_QEMU
```

The runs are interpreted (minutes): LPS's image fetch parses hex strings.

## Syscalls: NoCompiler's kernel model against LPS's specs

`lean/LPS/Bridge/Refine*.lean`. NoCompiler's function proofs step a syscall by NoCompiler's own model
(`procSpec7` over `Kern`). Two directions are needed per syscall:
- *forward* (`*_refines`, and the `*_admits` lemmas of `Bridge/Syscalls.lean`): an outcome NoCompiler allows is
  one LPS admits. This gives progress: where NoCompiler has a step, LPS has one.
- *converse* (`*_covers`): every outcome LPS admits is one NoCompiler allows. This is the direction that
  carries a NoCompiler theorem about every run to LPS's runs (NoCompiler over-approximates).

Done:

| Syscall | Direction | File | Hypotheses, besides the input and kernel relations |
|---|---|---|---|
| `close` | both | `RefineFd` | none |
| `exit_group` | both | `Refine`, `RefineSimple` | none (NoCompiler's status is all of a0, LPS's a0 & 255) |
| `set_tid_address` | converse | `RefineSimple` | a recorded tid is in range (`TidOk`) |
| `ioctl` | converse | `RefineSimple` | the request is `TIOCGWINSZ` (the only one NoCompiler models) |
| `writev` | converse | `RefineIo` | memory agreement (`MemAgree`), channel = fd (`ChanId`), the fd closed or an output channel, iovcnt < 2^32 (LPS reads its low 32 bits: the models disagree above), stdin with more than 1024 iovecs excluded |
| `brk` | converse | `RefineBrk` | the breaks related (`KernBrk`); the zeroed bytes agree on growth (`brk_zeros_agree`) |
| `read` | converse | `RefineRead` | `KernFd`, `ChanId`; the fd closed, a channel, a file NoCompiler has open, or one whose read is only an error (`ReadKind`); for a file, the buffer passes LPS's `access_ok` and is writable (`BufOk`); file offsets below 2^64 |
| `readv` | converse | `RefineReadv` | as `read` (`ReadvKind`), plus `MemAgree`, iovcnt < 2^32, at most 1024 iovecs on a channel other than stdin; a file readv LPS fails with EFAULT/EINVAL is a separate case (`ReadvFileErr`): NoCompiler has no such outcome |
| `mmap` | converse | `RefineMmap` | anonymous read-write with hint 0 (musl malloc's shape); each NoCompiler mapped range inside an LPS range (`KernMaps`); LPS's `alloc_top` within NoCompiler's `taskSize` |
| `mmap` with `MAP_FIXED` | converse | `RefineMmapFixed1-3` (`mmap_fixed_covers`) | `MAP_PRIVATE\|MAP_ANONYMOUS\|MAP_FIXED`, fd -1, offset 0, `PROT_NONE` or `PROT_READ\|PROT_WRITE`, `len > 0`; the address page-aligned (LPS checks wraparound before alignment, NoCompiler after: an unaligned, wrapping address gets ENOMEM from LPS, EINVAL from NoCompiler); `KernMaps`; LPS's `alloc_top` within `taskSize`. Covers LPS's contained, free and spanning cases, the injected ENOMEM and the destroy arm |
| `munmap` | converse | `RefineMunmap` | LPS's modeled inputs (page-aligned, `len > 0`, below `TASK_SIZE`, the whole mapping present); `KernMaps`; every LPS mapping at that base is the one unmapped (`MapSole`) |

The kernel relations: `KernFd` (descriptors and open files against `m_fds`/`m_fs`), `KernBrk`, `KernMaps`. Fd
arguments are read as their low 32 bits on both sides, and NoCompiler's read/write events are labelled with them
(user decisions (4), (6)): NoCompiler's `.write (i.fd 0) bs` against LPS's `bs.map (WriteEv ch)`, `ch = i.fd 0`
under `ChanId` (`EvAgree`).

Not yet: the converse for other `mmap` shapes (other prot values, `MAP_FIXED_NOREPLACE`, file mappings), `munmap` of part of a mapping, and the other syscalls LPS
models. No theorem yet composes these per-syscall refinements with `sim_sstep` into one statement about a whole
run.

## Open

- The run of check 3 is not a theorem. Its Boolean conditions are transcriptions of the lemmas'
  hypotheses (not yet proved equal), the spurious-refusal premise of `sstep_cfg_syscall` is not checked,
  and the whole run is not stated as one `star_cfg` trace.
- `codeAgree` on fuzz_qdisc plain is `true` by `#eval`, not by a kernel proof. `native_decide` is not used
  (user decision). The kernel route exists: images whose segments are numbers (`Bridge/HexStr`, `Bridge/HexImage`:
  `codeAgree_hex`, `codeAgreeH_of_ranges`), checked chunk by chunk (`Bridge/Chunks`: `codeFacts_ofChunks`), with
  `scripts/lps/gen_code_facts.py` generating one `decide +kernel` theorem per chunk from a `nocompiler export` and
  an image made with `elf_snapshot_lean.py --hex-form`. It has not completed on fuzz_qdisc: the one complete run
  (113 chunks, 8961 words; 695 s, 5.1 GB) failed only on a partial-range bug in `agreeRangeH`, since fixed, and
  the rerun was not made. Such a proof module holds the image, so it contains GPL-3.0 code: it is generated, not
  committed (NOTICE).
- `memcpy`/`memset` etc. proved for slen do not carry to fuzz_qdisc by relocation: the two binaries link
  different musl builds (`scripts/libc/reuse_measure.py`). `NoCompiler/Libc/Transfer.lean` and
  `NoCompiler/Libc/Relocate.lean` carry a process-level theorem to an image with the same words, or the
  same pcFree code at another address.
